# Information to gather for each tool

Copy the following for one tool at a time. Include official source links and the date you checked them. Mark unknown information as unknown; do not guess.

## Essential before publishing a complete profile

- Exact product name and official product URL (distinguish product, feature, model, and company).
- Short description: what it does, in one or two factual sentences.
- Detailed overview: how it works, what makes it useful, and what it does not do.
- Main category and relevant secondary categories/subcategories.
- 5–8 main features supported by official documentation.
- 3–5 practical use cases and the intended users.
- Pricing model and official pricing URL. Record plan names, prices, currency, billing period, annual-commitment conditions, and important usage limits.
- Free plan and free trial separately: limits, duration, and whether a payment card is required.
- Supported platforms, API availability, and documented integrations.
- Meaningful advantages and limitations, supported by evidence or disclosed testing.
- A few product-specific questions and sourced answers.
- Official sources and the date verified.

## Useful additional information

- Logo and screenshots you have permission to reuse, with captions and ALT text.
- Supported languages, input/output formats, export options, and regional restrictions.
- Privacy-policy URL, retention, training opt-out, and available data controls.
- Account/setup requirements, accessibility observations, and collaboration options.
- Alternatives already present in the directory and the reasons someone might choose each.
- Hands-on observations: test task, plan/version tested, result, date, and limitations. A documentation review must not be described as hands-on testing.

## What can be generated from that research

I can write the final page copy, SEO title, meta description, internal links, FAQs, and structured data from verified facts. You do not need to prepare code, Schema.org markup, or canonical URLs. Do not collect invented star ratings or keyword-stuffed text.

## Current import status

The supplied list contains names and category labels only. These are visible as `status: draft` entries with “Details pending” badges. They can be searched and filtered by category/subcategory, but are not classified as free, featured, popular, or reviewed. No thin individual profile pages are generated. Draft-only category and tool indexes stay noindex and out of the production sitemap.

To complete an entry, update its existing record in `data/tools.json`, fill the reviewed profile fields, set `status` to `published`, and run the build and validation. Keep the stable slug. Do not create a duplicate record. The template check runs in a separate temporary project.
